Seção de projetos — bancos de verdade

Chegou a hora de juntar as peças. Até aqui você aprendeu CREATE TABLE, INSERT, SELECT com JOIN, agregações, constraints e transações um a um. Agora a Ana vai montar quatro bancos completos, do tipo que sustenta sistemas de verdade: uma loja virtual, um blog, um sistema de reservas com controle de conflito e uma API Node.js conectada com pg.

Você vai aprender
  • A modelar tabelas que se relacionam com PRIMARY KEY e FOREIGN KEY (projeto loja).
  • A resolver relações N—N com tabela de ligação (projeto blog: posts × tags).
  • A proteger uma operação com BEGIN/COMMIT/ROLLBACK e evitar reserva duplicada (projeto reservas).
  • A conectar uma aplicação Node.js ao PostgreSQL com pg e pool de conexões (projeto API).
  • A ler os erros reais de integridade (chave duplicada, chave estrangeira) que esses projetos provocam.

Como funcionam os projetos

Cada projeto é um passo a passo curto, com o SQL completo nas caixas de arquivo (schema.sql, server.js…) e a saída real do psql nas caixas de terminal. Nas caixas Experimente você mesmo no terminal roda o psql simulado da máquina fictícia ana@notebook (PostgreSQL 16, banco loja_aurora, com as tabelas clientes, produtos, pedidos e itens_pedido): cada caixa tem uma missão — digite o comando pedido e, quando a saída certa aparecer, gagne o ✔ "Missão cumprida!". Se travar, clique em Ver comando; para zerar tudo, clique em Reiniciar.

Missão: antes de começar, digite \dt no terminal abaixo e veja as quatro tabelas que já existem no banco loja_aurora — é com elas que o projeto da loja trabalha.

Os quatro projetos

ProjetoO que você montaO que pratica
1. Loja virtualBanco da loja Aurora: clientes, produtos, pedidos e itens_pedido, com dados de exemplo e consultas de vendas.CREATE TABLE com PK/FK, INSERT, JOIN, GROUP BY + COUNT/SUM, erros 23505 e 23503
2. BlogPosts com comentários e tags — incluindo a relação N—N entre posts e tags via tabela de ligação.LEFT JOIN, tabela de ligação post_tags, CREATE VIEW, LIKE
3. Sistema de reservasReserva de itens com controle de conflito: duas pessoas não podem reservar o último exemplar.BEGIN/COMMIT/ROLLBACK, SELECT … FOR UPDATE, lock e transação ACID
4. API Node.js + pgAPI REST que lê e grava no banco loja_aurora usando o driver pg com pool.new Pool(), pool.query(), rotas Express, tratamento de erro de conexão

Pré-requisitos

  • Ter passado pelos três níveis: introdução, banco e tabelas, INSERT, SELECT, JOINs, agregações, constraints e transações.
  • Saber o básico do terminal: psql, \dt, setinha pra cima (histórico) e Ctrl+L para limpar.
  • Para o projeto 4, o básico de Node.js: npm init -y, npm install, node arquivo.js.

Missão: aqueça o psql simulado: digite SELECT * FROM clientes LIMIT 3; e veja os primeiros clientes da loja (a saída mostra Ana Souza e termina com (3 rows)).

Regra de bolso dos projetos: todo banco segue o mesmo roteiro — modelar (CREATE TABLE com PK/FK) → popular (INSERT) → consultar (SELECT com JOIN/GROUP BY) → proteger (transação + constraints) → conectar (aplicação com pool). Se travar, volte por esse roteiro; a página Problemas comuns cobre as trombadas típicas.
