Extensões: pg_trgm, PostGIS, uuid-ossp e outras

Pense nas extensões do PostgreSQL como os aplicativos que você instala no celular: o sistema vem básico, e cada extensão adiciona uma capacidade nova — busca aproximada de texto, mapas, UUIDs, estatísticas de queries. Instalar é um comando só: CREATE EXTENSION. Nesta aula: as extensões que mais caem em produção e o cuidado com código que roda dentro do servidor.

Você vai aprender
  • CREATE EXTENSION e como listar as disponíveis (pg_available_extensions);
  • uuid-ossp: gerar UUIDs com uuid_generate_v4() para chaves primárias não sequenciais;
  • pg_trgm: busca aproximada de texto com o operador % e índice GIN (gin_trgm_ops) para LIKE '%…%';
  • PostGIS: tipos geometry/geography, funções ST_Distance e busca "perto de mim";
  • Outras úteis: pg_stat_statements, citext, unaccent, hstore, pgcrypto;
  • O risco: extensões em C rodam dentro do processo do banco — só instale de fontes confiáveis;
  • Praticar busca de texto no psql simulado do banco loja_aurora.

Instalando uma extensão

Todas as extensões disponíveis no servidor aparecem na visão pg_available_extensions. Instalar é simples — e várias já vêm "prontas para instalar" na instalação padrão:

loja_aurora=> SELECT name, default_version, installed_version FROM pg_available_extensions
              WHERE name IN ('pg_trgm','uuid-ossp','postgis','pg_stat_statements','citext') ORDER BY name;
      name        | default_version | installed_version
------------------+-----------------+-------------------
 citext           | 1.6             | 
 pg_stat_statements | 1.10          | 
 pg_trgm          | 1.6             | 
 postgis          | 3.4.2           | 
 uuid-ossp        | 1.1             | 
(5 rows)
loja_aurora=> CREATE EXTENSION pg_trgm;
CREATE EXTENSION
loja_aurora=> CREATE EXTENSION "uuid-ossp";
CREATE EXTENSION
loja_aurora=> \dx
                 List of installed extensions
    Name     | Version |   Schema   |        Description
-------------+---------+------------+----------------------------
 pg_trgm     | 1.6     | public     | text similarity… trigram
 uuid-ossp   | 1.1     | public     | generate universally unique identifiers

O meta-comando \dx lista as extensões instaladas; DROP EXTENSION pg_trgm; remove (com CASCADE se objetos dependerem dela). Algumas extensões exigem superuser na criação (PostGIS, por exemplo) e algumas precisam de configuração extra no postgresql.conf — pg_stat_statements, por exemplo, exige shared_preload_libraries = 'pg_stat_statements' e restart.

uuid-ossp: chaves primárias que não revelam sequência

Em vez de id = 1, 2, 3… (que revela quantos registros existem e facilita chute de URLs), use UUIDs:

loja_aurora=> CREATE TABLE links_publicos (
loja_aurora(>   id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
loja_aurora(>   titulo text
loja_aurora(> );
CREATE TABLE
loja_aurora=> INSERT INTO links_publicos (titulo) VALUES ('relatorio 2026');
INSERT 0 1
loja_aurora=> SELECT * FROM links_publicos;
                  id                  |     titulo
--------------------------------------+------------------
 3f2a9c1e-7b4d-4e5f-9a0b-1c2d3e4f5a6b | relatorio 2026
(1 row)

Sem o DEFAULT uuid_generate_v4(), cada INSERT gera um id aleatório sozinho — bom para segurança (URLs impossíveis de adivinhar) e para sharding. (Em PG 13+ dá para usar a função built-in gen_random_uuid(), que não precisa de extensão.)

pg_trgm: busca de texto aproximada e rápida

O problema do LIKE '%Souza%' é que ele não usa índice B-tree — o banco varre a tabela inteira. A extensão pg_trgm (trigramas: sílabas de 3 letras) cria um índice GIN que até o LIKE '%…%' consegue usar, e ainda mede similaridade entre textos com o operador %:

loja_aurora=> CREATE INDEX idx_clientes_nome_trgm ON clientes USING gin (nome gin_trgm_ops);
CREATE INDEX
loja_aurora=> SELECT nome FROM clientes WHERE nome LIKE '%Souza%';
   nome
-----------
 Ana Souza
(1 row)
loja_aurora=> SELECT nome, similarity(nome, 'Ana Souza') AS similaridade
loja_aurora->   FROM clientes ORDER BY nome % 'Ana Souza' DESC LIMIT 3;
   nome    |   similaridade
-----------+------------------
 Ana Souza |                1
 Eva Nike  | 0.15384615384615385
 Beto Lima | 0.11111111111111111
(3 rows)

O operador % (similarity) e ORDER BY nome % 'Ana Souza' ordenam pelo mais parecido — é a base da busca "você quis dizer…?" dos mecanismos de busca.

PostGIS: o banco vira mapa

O PostGIS transforma o PostgreSQL no banco espacial mais usado do mundo: tipos geometry (plano) e geography (esfera terrestre, com lat/long reais), índices GiST e operadores de distância:

loja_aurora=> CREATE EXTENSION postgis;
CREATE EXTENSION
loja_aurora=> ALTER TABLE clientes ADD COLUMN localizacao geography(Point, 4326);
ALTER TABLE
loja_aurora=> UPDATE clientes SET localizacao = ST_SetSRID(ST_MakePoint(-42.79, -5.05), 4326) WHERE id = 1;
UPDATE 1
loja_aurora=> SELECT nome, ST_Distance(localizacao, ST_SetSRID(ST_MakePoint(-42.80, -5.06), 4326)) AS metros
loja_aurora->   FROM clientes ORDER BY localizacao <-> ST_SetSRID(ST_MakePoint(-42.80, -5.06), 4326) LIMIT 3;
   nome    |      metros
-----------+------------------
 Ana Souza | 1247.83…
 Eva Nike  | 1251.02…
 Beto Lima | 9876.54…
(3 rows)

O operador <-> (KNN) com índice GiST traz os pontos mais próximos primeiro sem varrer a tabela — é o "clientes perto de mim" do iFood/99. Ideal para mapas, rotas, entregas e qualquer dado com latitude/longitude.

Cuidado: a maioria das extensões é código em C que roda dentro do processo do servidor — um bug numa extensão pode derrubar o PostgreSQL inteiro ou abrir brecha de segurança. Só instale extensões de fontes confiáveis (pacotes oficiais do PostgreSQL, por exemplo apt install postgresql-16-postgis-3), mantenha atualizado junto com o servidor, e dê CREATE EXTENSION só para roles de confiança (várias exigem superuser).

Experimente: busca de texto no simulador

Missão: busca por prefixo (usa índice B-tree normal): digite SELECT nome FROM clientes WHERE nome LIKE 'A%'; e veja Ana Souza.

Missão: agora o caso que o pg_trgm resolve: SELECT nome FROM clientes WHERE nome LIKE '%Souza%'; — sem trigramas essa consulta faz Seq Scan; com o índice GIN do pg_trgm ela fica rápida mesmo em tabela gigante.

Missão: combine filtro e ordenação: SELECT nome FROM clientes WHERE estado = 'PI' ORDER BY nome DESC LIMIT 1; — a saída mostra Eva Nike.

Resumo

  • Extensão = plugin do servidor: CREATE EXTENSION nome;, lista com \dx, disponíveis em pg_available_extensions.
  • uuid-ossp: uuid_generate_v4() para PKs não sequenciais (ou gen_random_uuid() built-in no PG 13+).
  • pg_trgm: índice GIN gin_trgm_ops deixa LIKE '%…%' usar índice; operador % mede similaridade.
  • PostGIS: tipos geometry/geography, ST_Distance, KNN com <-> — banco vira mapa.
  • Também úteis: pg_stat_statements, citext, unaccent, hstore, pgcrypto.
  • Extensões em C rodam dentro do servidor: só instale de fontes confiáveis e mantenha atualizadas.
