UPDATE e DELETE com WHERE

UPDATE corrige uma ficha que já está arquivada e DELETE joga a ficha fora. Os dois funcionam só sobre as linhas que o WHERE escolher — e é exatamente aí que mora o perigo: sem WHERE, a tabela inteira é afetada. Nesta aula você aprende os dois com segurança.

Você vai aprender
  • UPDATE tabela SET coluna = valor WHERE ...; — e a resposta UPDATE n;
  • DELETE FROM tabela WHERE ...; — e a resposta DELETE n;
  • Por que o WHERE é o freio: sem ele, todas as linhas mudam/apagam;
  • Conferir com SELECT antes e depois;
  • Erro: relation "x" does not exist;
  • Praticar no simulador.

Corrigindo uma ficha: UPDATE

O Beto Lima (id 2) se mudou para Picos. Em vez de apagar a ficha e criar outra, você atualiza o campo cidade:

UPDATE clientes
SET cidade = 'Picos'
WHERE id = 2;
UPDATE clientes
a tabela cujas linhas vão mudar
SET cidade = 'Picos'
a coluna e o novo valor (pode ter várias, separadas por vírgula)
WHERE id = 2
quais linhas mudam — sem o WHERE, mudam TODAS
;
encerra e executa — a resposta UPDATE 1 diz quantas linhas mudaram
loja_aurora=> UPDATE clientes SET cidade = 'Picos' WHERE id = 2;
UPDATE 1
loja_aurora=> SELECT nome, cidade FROM clientes WHERE id = 2;
   nome    | cidade
-----------+--------
 Beto Lima | Picos
(1 row)

Apagando uma ficha: DELETE

DELETE FROM pedidos
WHERE id = 99;

A resposta DELETE 0 diz que nenhuma linha tinha id = 99 — o WHERE funcionou como filtro e não apagou nada. Se existisse, sairia DELETE 1.

loja_aurora=> DELETE FROM pedidos WHERE id = 99;
DELETE 0
loja_aurora=> DELETE FROM clientes WHERE estado = 'XX';
DELETE 0

O maior perigo do SQL: sem WHERE

UPDATE e DELETE sem WHERE afetam a tabela INTEIRA

UPDATE produtos SET preco = 0; não dá erro — dá UPDATE 5: todos os produtos da loja com preço zero! E DELETE FROM clientes; apaga todas as fichas. O psql não pede confirmação. Regra de ouro: escreva o WHERE, teste o filtro com um SELECT primeiro (SELECT * FROM produtos WHERE ...;), e só então rode o UPDATE/DELETE. No Nível 2 você verá que BEGIN; … ROLLBACK; salva até de um comando desses.

Erros comuns

loja_aurora=> UPDATE tabela_fantasma SET x = 1;
ERROR:  relation "tabela_fantasma" does not exist
loja_aurora=> DELETE FROM tabela_fantasma;
ERROR:  relation "tabela_fantasma" does not exist

Tabela errada → relation "x" does not exist. Sempre confira o nome com \dt.

Pratique

Missão: mude a cidade do cliente 2: UPDATE clientes SET cidade = 'Picos' WHERE id = 2; → UPDATE 1.

Missão: confira a mudança: SELECT nome, cidade FROM clientes WHERE id = 2; → a saída mostra Picos.

Missão: tente apagar um pedido que não existe: DELETE FROM pedidos WHERE id = 99; → DELETE 0 (nenhuma linha apagada).

Missão: atualize uma tabela fantasma: UPDATE tabela_fantasma SET x = 1; → ERROR: relation "tabela_fantasma" does not exist.

Resumo

  • UPDATE t SET col = valor WHERE ...; → UPDATE n (n linhas mudaram).
  • DELETE FROM t WHERE ...; → DELETE n (n linhas apagadas).
  • Sem WHERE = tabela inteira afetada. Sempre teste o filtro com SELECT antes.
  • Tabela errada: relation "x" does not exist — confira com \dt.
