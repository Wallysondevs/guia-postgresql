Tipos de dados: cada campo da ficha tem seu tipo

Na planilha clientes, a coluna nome é text e a coluna id é integer. O tipo é o rótulo do campo da ficha: ele diz o que pode entrar ali — e o PostgreSQL rejeita o que não bate (no campo "data" não entra a palavra "banana"). Nesta aula, os tipos que você mais vai usar.

Você vai aprender
  • Texto: text, varchar(n), char(2);
  • Números: integer, bigint, numeric(10,2) (dinheiro) e por que não usar float para dinheiro;
  • date/timestamp, boolean, jsonb e serial;
  • No simulador: criar teste_tipos, ver a estrutura com \d e inserir uma linha.

Dinheiro é numeric, nunca float

Parece estranho, mas em ponto flutuante 0.1 + 0.2 dá 0.30000000000000004 — erro de arredondamento que, somado em milhões de vendas, vira dinheiro perdido. O numeric(10,2) é exato: guarda 10 dígitos no total, 2 depois da vírgula. Regra de bolso: preço e valor monetário → sempre numeric; medidas científicas (que toleram aproximação) → float.

jsonb: quando a ficha tem campos extras

Às vezes uma linha precisa de dados que não têm coluna fixa — as preferências de um cliente, por exemplo. Aí entra o jsonb: um campo que guarda um JSON inteiro ('{"tema": "escuro", "notificacoes": true}') e ainda permite consultar dentro dele. É o melhor dos dois mundos: a rigidez da planilha + a liberdade do JSON.

Na prática: criando uma tabela de tipos variados

loja_aurora=> CREATE TABLE teste_tipos (
loja_aurora->   id integer PRIMARY KEY,
loja_aurora->   nome text,
loja_aurora->   preco numeric(10,2),
loja_aurora->   ativo boolean,
loja_aurora->   criado_em date,
loja_aurora->   dados jsonb
loja_aurora-> );
CREATE TABLE
loja_aurora=> INSERT INTO teste_tipos (nome, preco, ativo, criado_em, dados)
loja_aurora-> VALUES ('Caneca', 29.90, true, '2026-11-24', '{}');
INSERT 0 1
loja_aurora=> \d teste_tipos
Table "public.teste_tipos"
+-----------+--------------+----------------+
| Column    | Type         | Modifiers      |
+-----------+--------------+----------------+
| id        | integer      | PRIMARY KEY    |
| nome      | text         |                |
| preco     | numeric(10,2)|                |
| ativo     | boolean      |                |
| criado_em | date         |                |
| dados     | jsonb        |                |
+-----------+--------------+----------------+

O \d teste_tipos é o "raio-x" da planilha: mostra cada coluna, seu tipo e suas restrições. Repare que o id não entrou no INSERT — como é PRIMARY KEY (serial), o banco preenche sozinho.

Pratique

Missão: crie a tabela de teste: CREATE TABLE teste_tipos (id integer PRIMARY KEY, nome text, preco numeric(10,2), ativo boolean, criado_em date, dados jsonb); → CREATE TABLE.

Missão: abra o raio-x da tabela: \d teste_tipos. A saída mostra a coluna dados do tipo jsonb.

Missão: insira uma linha com vários tipos de uma vez: INSERT INTO teste_tipos (nome, preco, ativo, criado_em, dados) VALUES ('Caneca', 29.90, true, '2026-11-24', '{}'); → INSERT 0 1.

Resumo

  • Cada coluna tem um tipo, e o banco rejeita valor fora do tipo.
  • Texto: text / varchar(n) / char(n) · Inteiro: integer, bigint, serial (auto-incremento).
  • Dinheiro → numeric(10,2) (exato); float é só para medida científica.
  • date/timestamp, boolean, jsonb para dados flexíveis.
  • \d tabela mostra a estrutura inteira: colunas, tipos e restrições.
