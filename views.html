Views: consultas salvas com nome

Tem uma consulta que você digita toda hora? Uma view é exatamente isso: um SELECT que ganhou nome e foi salvo no banco — como dar um apelido para uma fórmula comprida da planilha. Depois você consulta a view como se fosse uma tabela, e nem precisa lembrar do SQL original.

Você vai aprender
  • CREATE VIEW nome AS SELECT ...;
  • Consultar a view: SELECT * FROM nome;;
  • View com JOIN;
  • CREATE OR REPLACE VIEW e DROP VIEW;
  • Para que serve: simplificar queries e esconder colunas sensíveis (e-mail).

Criando a primeira view

Queremos sempre os clientes do Piauí. Em vez de digitar o WHERE toda vez, salvamos a consulta numa view chamada clientes_pi:

CREATE VIEW clientes_pi AS
SELECT nome, cidade, estado
FROM clientes
WHERE estado = 'PI';
CREATE VIEW clientes_pi
cria a view e dá o nome dela: clientes_pi.
AS SELECT ...
a consulta que fica salva dentro da view — ela roda toda vez que alguém consultar a view.
loja_aurora=> CREATE VIEW clientes_pi AS SELECT nome, cidade FROM clientes WHERE estado = 'PI';
CREATE VIEW
loja_aurora=> SELECT * FROM clientes_pi;
   nome    |  cidade   | estado
-----------+-----------+--------
 Ana Souza | Teresina  | PI
 Beto Lima | Parnaíba  | PI
 Eva Nike  | Teresina  | PI
(3 rows)

Viagem no tempo: depois do CREATE VIEW, a consulta virou SELECT * FROM clientes_pi; — curtinha. A view não guarda dados copiados: ela guarda a consulta e a executa na hora, sempre mostrando os dados atualizados da tabela.

No simulador: o CREATE VIEW responde CREATE VIEW e registra o nome, mas não dá para fazer SELECT em cima da view (ele só conhece tabelas). Para ver as linhas, rode o SELECT original — é exatamente o que a view executaria por baixo.

Missão: crie a view clientes_pi com o SELECT dos clientes de 'PI'. O psql confirma com CREATE VIEW.

Missão: veja o que a view clientes_pi mostraria: rode o SELECT original — SELECT nome, cidade FROM clientes WHERE estado = 'PI'; — e confira as (3 rows) (Ana Souza, Beto Lima e Eva Nike).

View com JOIN

Views brilham quando a consulta é grande — com JOIN, então, nem se fala. Quer ver cada pedido junto com o nome do cliente, sem digitar o JOIN toda vez?

CREATE VIEW pedidos_resumo AS
SELECT p.id AS pedido, c.nome AS cliente, p.status
FROM pedidos p
JOIN clientes c ON p.cliente_id = c.id;

Para que servent as views

  • Simplificar: SELECT * FROM clientes_pi; em vez de repetir o SELECT grande com WHERE e JOIN.
  • Segurança: crie uma view sem a coluna email e dê permissão só nela — quem consulta não vê dados sensíveis da tabela original.
  • Reuso: mudou a consulta? CREATE OR REPLACE VIEW troca a definição e todas as aplicações acompanham.
ComandoO que faz
CREATE VIEW v AS SELECT ...;salva a consulta com o nome v
SELECT * FROM v;consulta a view como se fosse tabela (roda o SELECT salvo na hora)
CREATE OR REPLACE VIEW v AS ...;troca a definição da view sem precisar apagar
DROP VIEW v;apaga a view (os dados da tabela original continuam lá)

Resumo

  • View = SELECT salvo com nome no banco: CREATE VIEW v AS SELECT ...;
  • Depois você consulta como tabela: SELECT * FROM v; — a view não copia dados, roda a consulta na hora.
  • Ótima para simplificar JOINs e dar acesso só a parte das colunas (segurança).
  • CREATE OR REPLACE VIEW altera a definição; DROP VIEW apaga a view.
