Cola de tipos de dados do PostgreSQL

O tipo de cada coluna é a primeira linha de defesa do banco: o PostgreSQL recusa dado que não cabe no tipo (invalid input syntax). Pense no tipo como o tamanho da gaveta do arquivo: texto vai em gaveta de texto, número em gaveta de número, data em gaveta de data. Esta cola lista os que você mais usa e quando escolher cada um.

Você vai aprender
  • Texto: text (ilimitado, preferido), varchar(n), char(n).
  • Números: integer, bigint, numeric(p,s) (exato — dinheiro), real/double precision (aproximado).
  • Data/hora: date, timestamp, timestamptz, interval · boolean · jsonb · uuid.
  • Sequências: serial/bigserial (id auto-incremento).

Texto

TipoExemploQuando usar
textnome textO padrão para texto — sem limite de tamanho. Prefira sempre.
varchar(n)email varchar(255)texto com limite (valida tamanho máximo); n é o máximo de caracteres.
char(n)estado char(2)texto de tamanho fixo que o banco preenche com espaços (ex.: 'PI', código de país).

Números

TipoFaixaQuando usar
smallint−32.768 … 32.767contagens pequenas (nota de 0 a 10, estoque baixo).
integer± ~2,1 bilhõeso padrão para inteiros (id, quantidade, idade).
bigint± ~9 quintilhõesids muito grandes, contadores de rede social, timestamps em ms.
numeric(p,s)exato, até 131.072 dígitosdinheiro e valores exatos — numeric(10,2) guarda 59.90 sem erro de arredondamento.
real / double precisionponto flutuante (aproximado)medições científicas. Nunca para dinheiro (0.1 + 0.2 ≠ 0.3).
serial / bigserialinteger/bigint auto-incrementoid de tabela: o banco gera solo (1, 2, 3…).
Armadilha: numeric é exato, real/double é aproximado. Para preço use numeric(10,2) — com float, 59.90 pode virar 59.900000000000006.

Um CREATE TABLE com tudo

CREATE TABLE produtos (
  id          serial PRIMARY KEY,          -- inteiro auto-incremento
  sku         uuid DEFAULT gen_random_uuid(),
  nome        varchar(100) NOT NULL,
  descricao   text,
  preco       numeric(10,2) CHECK (preco >= 0),  -- dinheiro: exato
  estoque     integer DEFAULT 0,
  ativo       boolean DEFAULT true,
  criado_em   timestamptz DEFAULT now(),
  entrega     date,
  atributos   jsonb,                       -- ex.: {"cor": "azul", "tamanho": "M"}
  tags        text[]
);

Missão: monte uma tabela com vários tipos no simulador: CREATE TABLE exemplo (id uuid PRIMARY KEY, nome varchar(100) NOT NULL, preco numeric(10,2), dados jsonb, criado_em timestamp); — o servidor responde CREATE TABLE.

Missão: confira a tabela criada: \d exemplo — a saída mostra as colunas com PRIMARY KEY no id.
