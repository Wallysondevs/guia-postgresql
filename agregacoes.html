Agregações: COUNT, SUM, AVG, MIN, MAX + GROUP BY

Até aqui o SELECT listava linhas. Agora vamos resumir: quantos pedidos existem? Quanto temos em estoque? Qual o preço médio? As funções de agregação transformam várias linhas em um único valor — e o GROUP BY faz isso por grupo (por estado, por status), como totalizar uma planilha por categoria.

Você vai aprender
  • COUNT, SUM, AVG, MIN, MAX — um resumo da tabela inteira;
  • GROUP BY — quebrar em grupos e agregar dentro de cada um;
  • HAVING — filtrar depois de agregar (o WHERE filtra antes);
  • Agregações combinadas com JOIN (valor de cada pedido);
  • Erros comuns: agregação no WHERE e coluna esquecida no GROUP BY;
  • Praticar no simulador de psql.

As cinco funções de agregação

Num banco de dados, "resumo" é a pergunta mais comum do dia a dia: "quantos?", "quanto?", "qual o maior?". No psql da ana@notebook, no banco loja_aurora:

loja_aurora=> SELECT COUNT(*) FROM pedidos;
 count
-------
     3
(1 row)

loja_aurora=> SELECT SUM(estoque) AS total_estoque FROM produtos;
 total_estoque
---------------
           285
(1 row)

loja_aurora=> SELECT MIN(preco) AS menor, MAX(preco) AS maior FROM produtos;
 menor | maior
-------+-------
  4.50 | 59.90
(1 row)

loja_aurora=> SELECT ROUND(AVG(preco), 2) AS media_preco FROM produtos;
 media_preco
-------------
       32.82
(1 row)
FunçãoO que fazExemplo
COUNT(*)conta linhasCOUNT(*) FROM pedidos → 3
COUNT(col)conta valores não nulos da colunadifere do * quando há NULL
SUM(col)soma os valoresSUM(estoque) → 285
AVG(col)média aritméticaAVG(preco) → 32.82 (com ROUND)
MIN(col) / MAX(col)menor / maior valorMIN(preco) → 4.50, MAX(preco) → 59.90

pormenor: AVG de coluna numeric sai com várias casas decimais no psql real — é por isso que usamos ROUND(AVG(preco), 2) para deixar bonitinho.

GROUP BY: agregar por grupo

Sem GROUP BY, a agregação resume a tabela inteira numa linha só. Com GROUP BY, o PostgreSQL quebra as linhas em grupos — uma "caixinha" por estado — e calcula a agregação dentro de cada caixinha:

loja_aurora=> SELECT estado, COUNT(*) FROM clientes GROUP BY estado;
 estado | count
--------+-------
 PI     |     3
 SP     |     1
 PE     |     1
(3 rows)
SELECT estado, COUNT(*)
a coluna do grupo + a função de agregação
FROM clientes
a "planilha" de origem
GROUP BY estado
quebra as linhas em grupos pelo estado — cada grupo vira uma linha de saída

HAVING: filtrar depois de agregar

O WHERE filtra antes de agregar (linhas individuais); o HAVING filtra depois (grupos já calculados). A pergunta "quais estados têm mais de 1 cliente?" só dá para responder com HAVING:

loja_aurora=> SELECT estado, COUNT(*) AS total
             FROM clientes
             GROUP BY estado
             HAVING COUNT(*) > 1;
 estado | total
--------+-------
 PI     |     3
(1 row)
GROUP BY estado
forma os grupos primeiro
HAVING COUNT(*) > 1
descarta os grupos cuja contagem não passa no teste — só o PI sobrou
Erros comuns na hora de agregar

1) Usar agregação no WHERE — o WHERE trabalha com linhas, não com grupos:

loja_aurora=> SELECT estado, COUNT(*) FROM clientes WHERE COUNT(*) > 1 GROUP BY estado;
ERROR:  aggregate functions are not allowed in WHERE
LINE 1: SELECT estado, COUNT(*) FROM clientes WHERE COUNT(*) > 1 GROUP BY estado;
                                                 ^

2) Escrever uma coluna solta e esquecer o GROUP BY — ou a coluna entra no GROUP BY, ou vai dentro de uma agregação:

loja_aurora=> SELECT estado, COUNT(*) FROM clientes;
ERROR:  column "clientes.estado" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT estado, COUNT(*) FROM clientes;
               ^

Agregando com JOIN: valor de cada pedido

Agregação combina lindamente com JOIN (aula anterior). Aqui somamos qtd × preco dos itens dentro de cada pedido:

loja_aurora=> SELECT p.id AS pedido, SUM(i.qtd * i.preco) AS total
             FROM pedidos p
             JOIN itens_pedido i ON i.pedido_id = p.id
             GROUP BY p.id
             ORDER BY p.id;
 pedido |  total
--------+----------
      1 | 133.30
      2 |  29.90
      3 |  49.90
(3 rows)

O pedido 1 deu 133.30 porque a Ana levou 2 camisetas (2 × 59.90) + 3 adesivos (3 × 4.50). Repare que p.id entrou no GROUP BY — regra de ouro: tudo que não é agregação precisa estar no GROUP BY.

Missões no simulador

Abra o terminal e cumpra as missões:

Missão 1: conte os pedidos: SELECT COUNT(*) FROM pedidos; deve mostrar 3.

Missão 2: agrupe os clientes por estado com GROUP BY estado — a saída mostra os grupos PI, SP e PE.

Missão 3: some o estoque todo: SELECT SUM(estoque) FROM produtos; deve dar 285.

Missão 4: tire a média de preço: SELECT AVG(preco) FROM produtos; deve mostrar 32.82.

Missão 5: use HAVING para mostrar só o estado com mais de 1 cliente: SELECT estado, COUNT(*) AS total FROM clientes GROUP BY estado HAVING total > 1; — só o PI sobra.

Resumo

  • COUNT / SUM / AVG / MIN / MAX resumem várias linhas num valor só.
  • GROUP BY col calcula a agregação por grupo; tudo que não é agregação precisa estar no GROUP BY.
  • WHERE filtra linhas antes de agregar; HAVING filtra grupos depois.
  • Erros: aggregate functions are not allowed in WHERE e must appear in the GROUP BY clause.
