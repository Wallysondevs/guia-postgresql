O que é PostgreSQL e por que usar

PostgreSQL é um banco de dados relacional open source — um programa que fica rodando no servidor, guarda seus dados de forma organizada e responde perguntas sobre eles em milissegundos. Ele fala SQL, a linguagem padrão dos bancos relacionais, e é a escolha de quem não pode perder dados: Instagram, Spotify e a NASA o usam. Nesta aula: a ideia central, a analogia do arquivo e por que escolher o PostgreSQL.

Você vai aprender
  • O que é um banco de dados relacional — banco = arquivo, tabela = planilha, linha = registro;
  • O que é SQL e por que você diz o quê quer, não como buscar;
  • Quem são o servidor (PostgreSQL) e o cliente (psql);
  • Por que PostgreSQL — e como ele se compara a MySQL e SQLite;
  • Praticar no psql simulado desta página (máquina ana@notebook, PostgreSQL 16, banco loja_aurora).

A analogia do arquivo de planilhas

Pense no servidor de banco de dados como um arquivo de planilhas bem guardado:

  • o banco de dados (database) é o arquivo inteiro — ex.: loja_aurora;
  • cada tabela é uma planilha dentro do arquivo — ex.: clientes, produtos, pedidos;
  • cada linha é um registro, uma ficha preenchida — ex.: a ficha da Ana Souza;
  • cada coluna é um campo da ficha — nome, email, cidade, estado.

O PostgreSQL é o arquivista: você faz um pedido em SQL e ele traz a ficha certa na hora — sem você precisar saber em qual gaveta ela está.

SQL: você diz o quê, não como

SQL é uma linguagem declarativa: você descreve o resultado desejado, e o banco escolhe o melhor caminho para chegar lá. Repare na frase:

SELECT nome, estado FROM clientes WHERE estado = 'PI';

Em português: "selecione nome e estado dos clientes onde o estado é PI". Você não disse "percorra a planilha linha a linha e compare" — o PostgreSQL faz isso sozinho, e faz rápido mesmo com milhões de fichas. Veja na máquina da Ana (ana@notebook, PostgreSQL 16, banco loja_aurora):

loja_aurora=> SELECT nome, estado FROM clientes WHERE estado = 'PI';
   nome    | estado
-----------+--------
 Ana Souza | PI
 Beto Lima | PI
 Eva Nike  | PI
(3 rows)

Por que PostgreSQL? (vs MySQL e SQLite)

Os três são bancos usados no dia a dia — a diferença é onde e quão crítico é o dado:

BancoO que éGuarda os dados emIdeal para
PostgreSQLrelacional open source completo (ACID, tipos fortes, JSON, extensões)no servidor, em tabelasquando o dado não pode errar: financeiro, logística, saúde
MySQLrelacional open source com foco em webno servidor, em tabelassites e blogs (ex.: WordPress)
SQLitebanco inteiro dentro de um arquivo, sem servidorum arquivo .db dentro do appcelular e app embarcado (cada celular tem o seu)

Regra de bolso: app no celular → SQLite; site na web → MySQL; sistema que não pode perder nem corromper dados → PostgreSQL. Neste guia vamos de PostgreSQL, o mais completo dos três.

Servidor e cliente: quem é quem

O PostgreSQL é o servidor: fica rodando em segundo plano, ouvindo a porta 5432, guardando os arquivos do banco. O psql é o cliente de terminal: um programa que você abre, digita comandos SQL e vê a resposta na tela. Na nossa máquina fictícia ana@notebook já está tudo pronto: PostgreSQL 16 no ar e o banco loja_aurora com 4 tabelas.

Missão: digite SELECT * FROM clientes LIMIT 3; e aperte Enter. Você pediu as 3 primeiras fichas da planilha clientes — a saída mostra Ana Souza e (3 rows).

Missão: agora rode \dt. O psql lista as 4 planilhas do banco loja_aurora: clientes, produtos, pedidos e itens_pedido.

Resumo

  • Banco relacional = arquivo de planilhas no servidor; tabela = planilha; linha = registro; coluna = campo.
  • SQL é declarativo: SELECT ... FROM ... WHERE ... diz o quê você quer, e o banco acha como.
  • PostgreSQL: open source, confiável, tipos fortes e JSON — a escolha para dados críticos (vs MySQL para web e SQLite para arquivo local).
  • Servidor = PostgreSQL na porta 5432; cliente = psql no terminal.
