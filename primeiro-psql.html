Seu primeiro psql: conectar, bancos e sair

O psql é o cliente de terminal do PostgreSQL — a janelinha onde você conversa com o arquivista. Nesta aula você entra, lista os bancos, troca de banco, olha as tabelas e sai. Tudo isso na máquina fictícia ana@notebook, que já tem o PostgreSQL 16 rodando com o banco loja_aurora.

Você vai aprender
  • Entrar no psql: psql -U postgres ou direto no banco com psql -U ana -d loja_aurora;
  • Ler o prompt: loja_aurora=> diz em qual banco você está;
  • \l lista os bancos, \c banco troca de banco, \dt lista as tabelas;
  • Banco vazio: \dt responde Did not find any relations.;
  • \q sai de volta para o shell;
  • Praticar tudo isso no simulador desta página.

Entrando e lendo o prompt

Para entrar no psql você diz o usuário (-U) e, se quiser, o banco (-d):

$ psql -U ana -d loja_aurora   ← -U ana (usuário), -d loja_aurora (banco)
psql (16.4)
Type "help" for help.

loja_aurora=>

O prompt é a parte antes do cursor: loja_aurora=> diz "você está conectado no banco loja_aurora, como usuário normal". Se você entra como superusuário, o prompt termina em # (postgres=#) — um aviso visual de que seus comandos são poderosos.

\l, \c e \dt: passeando pelos bancos

$ psql -U ana -d loja_aurora
psql (16.4)

loja_aurora=> \l
+--------------+--------------+
| Name         | Owner        |
+--------------+--------------+
| postgres     | ana          |
| loja_aurora  | ana          |
+--------------+--------------+
(2 rows)

loja_aurora=> \c postgres
You are now connected to database "postgres" as user "ana".

postgres=> \dt
Did not find any relations.

postgres=> \c loja_aurora
You are now connected to database "loja_aurora" as user "ana".

loja_aurora=> \dt
+--------------+--------------+
| Name         | Owner        |
+--------------+--------------+
| clientes     | ana          |
| produtos     | ana          |
| pedidos      | ana          |
| itens_pedido | ana          |
+--------------+--------------+
(4 rows)

loja_aurora=> \q
$

Três meta-comandos fazem o passeio:

\l
lista os bancos do servidor (pense: "quais arquivos eu tenho?")
\c postgres
troca para outro banco — o prompt muda na hora (viu? virou postgres=>)
\dt
lista as tabelas do banco atual ("quais planilhas tem nesse arquivo?")

Repare: no banco postgres o \dt disse Did not find any relations. — banco novo é arquivo vazio, sem planilha nenhuma. Já o loja_aurora tem as 4 planilhas da loja.

Meta-comando não é SQL

Tudo que começa com \ é meta-comando do psql — o próprio cliente interpreta, e ele não precisa de ponto-e-vírgula. SQL de verdade (como SELECT) precisa do ; para executar. Se você digitar \c com ; no final, o psql reclama: meta-comando não leva ;.

\c
"connect": o comando de troca de banco
loja_aurora
o argumento: o nome do banco para onde você vai

Erros comuns de primeira vez

loja_aurora=> \c nao_existe
FATAL:  database "nao_existe" does not exist
loja_aurora=> \q

Conectar em banco que não existe dá FATAL e o psql fecha — cheque o nome com \l antes. E para sair, \q (ou Ctrl+D) devolve você ao shell, onde o prompt vira $ de novo.

Pratique

Missão: rode \dt e veja as 4 tabelas do banco loja_aurora (a última é itens_pedido).

Missão: rode \l e confira os 2 bancos do servidor: postgres e loja_aurora.

Missão: rode \c postgres e depois \dt — o banco postgres está vazio (Did not find any relations.). Volte com \c loja_aurora.

Missão: rode \q para sair do psql (no simulador, a mensagem diz que o psql foi encerrado — use o botão Reiniciar para continuar).

Resumo

  • Entrar: psql -U ana -d loja_aurora; o prompt loja_aurora=> mostra o banco atual (# = superusuário).
  • \l lista bancos · \c banco troca de banco · \dt lista tabelas · \q sai.
  • Meta-comandos (\...) são do psql, não vão ao servidor e não levam ;.
  • Banco vazio: \dt → Did not find any relations.; banco inexistente: FATAL: database "x" does not exist.
