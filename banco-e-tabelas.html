CREATE DATABASE e CREATE TABLE

Agora que você sabe passear pelo psql, vamos criar coisas: primeiro o arquivo (CREATE DATABASE) e depois a planilha dentro dele (CREATE TABLE). É aqui que a loja loja_aurora nasceu — e é aqui que você vai criar o seu banco de testes.

Você vai aprender
  • CREATE DATABASE loja_teste; e \c para trocar de banco;
  • CREATE TABLE com a lista de colunas e seus tipos;
  • PRIMARY KEY, NOT NULL e UNIQUE na prática;
  • O erro relation "x" already exists ao criar de novo;
  • Banco novo é banco vazio: \dt → Did not find any relations.
  • Praticar no simulador.

Criando o "arquivo": CREATE DATABASE

Criar um banco é como criar um arquivo novo no servidor. Depois de criar, você precisa entrar nele com \c — o psql só cria, não conecta sozinho:

postgres=> CREATE DATABASE loja_teste;
CREATE DATABASE
postgres=> \c loja_teste
You are now connected to database "loja_teste" as user "ana".
loja_teste=> \dt
Did not find any relations.

Banco criado e vazio: o \dt não achou nenhuma planilha. Agora vamos criar a primeira tabela dentro dele:

loja_teste=> CREATE TABLE categorias (
loja_teste->   id integer PRIMARY KEY,
loja_teste->   nome text NOT NULL
loja_teste-> );
CREATE TABLE
loja_teste=> \dt
+--------------+--------------+
| Name         | Owner        |
+--------------+--------------+
| categorias   | ana          |
+--------------+--------------+
(1 row)

Repare no psql: enquanto o comando não tem ;, o prompt vira loja_teste-> (com -) e espera a próxima linha. O ; é o sinal de "pode executar".

A planilha clientes da loja_aurora

O banco loja_aurora tem 4 tabelas. A principal é a clientes, criada assim:

CREATE TABLE clientes (
  id         integer PRIMARY KEY,
  nome       text NOT NULL,
  email      text UNIQUE,
  cidade     text,
  estado     char(2),
  criado_em  date DEFAULT CURRENT_DATE
);
CREATE TABLE
o comando que cria uma tabela nova
clientes
o nome da tabela — a convenção é plural e minúsculo
( ... )
a lista de colunas, entre parênteses, separada por vírgula
nome text NOT NULL
uma coluna: nome, do tipo text, obrigatória (não pode ficar vazia)
id integer PRIMARY KEY
a chave primária: um número único que identifica cada ficha (linha)
email text UNIQUE
o email não pode se repetir em duas linhas
;
o ponto-e-vírgula encerra e executa o comando

As 4 planilhas da loja

loja_aurora=> \dt
+--------------+--------------+
| Name         | Owner        |
+--------------+--------------+
| clientes     | ana          |
| produtos     | ana          |
| pedidos      | ana          |
| itens_pedido | ana          |
+--------------+--------------+
(4 rows)
  • clientes — as fichas dos clientes (Ana Souza, Beto Lima…);
  • produtos — o catálogo (Camiseta, Caneca, Adesivo…) com preço e estoque;
  • pedidos — cada pedido liga um cliente (cliente_id) a uma data e um status;
  • itens_pedido — os itens de cada pedido, ligando pedido e produto.

Quando o banco barra: tabela já existe

CREATE TABLE em nome repetido dá erro

Se você tentar criar clientes de novo no loja_aurora, o PostgreSQL protege seus dados e responde ERROR: relation "clientes" already exists. Para apagar de verdade existe o DROP TABLE clientes; — mas ele apaga a tabela e todos os dados, sem lixeira. Cuidado.

loja_aurora=> CREATE TABLE clientes (id integer PRIMARY KEY, nome text);
ERROR:  relation "clientes" already exists

Pratique

Missão: crie um banco novo: digite CREATE DATABASE loja_teste;. A confirmação é CREATE DATABASE.

Missão: entre no banco novo com \c loja_teste e rode \dt — banco vazio, Did not find any relations. (depois volte com \c loja_aurora).

Missão: crie sua primeira tabela: CREATE TABLE categorias (id integer PRIMARY KEY, nome text NOT NULL); → CREATE TABLE. Rode \dt para ver a categorias na lista.

Missão: tente recriar a tabela clientes: CREATE TABLE clientes (id integer PRIMARY KEY, nome text);. O banco barra: already exists.

Resumo

  • CREATE DATABASE nome; cria o arquivo; \c nome entra nele.
  • CREATE TABLE nome (coluna tipo restrições, ...); cria a planilha; o ; executa.
  • PRIMARY KEY = identificador único da linha · NOT NULL = obrigatória · UNIQUE = não repete.
  • Criar de novo dá relation "x" already exists; DROP TABLE apaga tudo — cuidado.
