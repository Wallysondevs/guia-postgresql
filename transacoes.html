Transações: BEGIN, COMMIT e ROLLBACK

Imagine a reserva de um produto: o sistema precisa dar baixa no estoque e registrar o pedido — e o servidor cai entre uma coisa e outra. Resultado: estoque baixou, mas o pedido não existe. Uma transação é o pacote "tudo ou nada": ou todas as operações acontecem, ou nenhuma. No PostgreSQL você controla isso com BEGIN, COMMIT e ROLLBACK.

Você vai aprender
  • BEGIN; — inicia a transação (o prompt vira loja_aurora*>);
  • COMMIT; — confirma tudo de vez;
  • ROLLBACK; — desfaz tudo, voltando ao ponto do BEGIN;
  • O exemplo clássico: reserva de estoque com UPDATE + INSERT;
  • ACID: atomicidade, consistência, isolamento e durabilité.

BEGIN: nada é definitivo até o COMMIT

O BEGIN abre a transação. Repare no detalhe visual: o prompt muda de loja_aurora=> para loja_aurora*> — o * avisa que você está dentro de uma transação e nada foi confirmado ainda:

loja_aurora=> BEGIN;
BEGIN
loja_aurora*=>

O exemplo da reserva de estoque

Ana vai comprar a camiseta (id 1, estoque 20). A reserva são duas operações que precisam acontecer juntas: dar baixa no estoque e criar o pedido:

loja_aurora=> BEGIN;
BEGIN
loja_aurora*=> UPDATE produtos SET estoque = 19 WHERE id = 1;
UPDATE 1
loja_aurora*=> INSERT INTO pedidos (cliente_id) VALUES (1);
INSERT 0 1
loja_aurora*=> SELECT estoque FROM produtos WHERE id = 1;
 estoque
---------
      19
(1 row)
UPDATE produtos
a tabela que vai mudar.
SET estoque = 19
a coluna e o novo valor.
WHERE id = 1
quais linhas mudam — sem o WHERE, o UPDATE altera a tabela inteira!

ROLLBACK: deu errado? desfaz tudo

Se no meio da reserva deu algum problema (cliente desistiu, pagamento recusado), o ROLLBACK desfaz todas as operações desde o BEGIN — é como apertar "desfazer" no editor, mas para o banco inteiro:

loja_aurora*=> ROLLBACK;
ROLLBACK
loja_aurora=> SELECT estoque FROM produtos WHERE id = 1;
 estoque
---------
      20
(1 row)

O estoque voltou a 20 e o pedido não foi criado — o banco voltou exatamente ao estado de antes do BEGIN.

Missão: faça uma reserva e desfaça: digite BEGIN;, depois UPDATE produtos SET estoque = 0 WHERE id = 1; e por fim ROLLBACK;. Depois rode SELECT estoque FROM produtos WHERE id = 1; e confirme que voltou a 20.

COMMIT: agora sim, vale para sempre

Se estava tudo certo, o COMMIT grava de vez todas as operações da transação — depois dele não existe "desfazer":

loja_aurora=> BEGIN;
BEGIN
loja_aurora*=> UPDATE produtos SET estoque = 19 WHERE id = 1;
UPDATE 1
loja_aurora*=> COMMIT;
COMMIT
loja_aurora=> SELECT estoque FROM produtos WHERE id = 1;
 estoque
---------
      19
(1 row)

Missão: inicie uma transação com BEGIN; — repare que o prompt do simulador vira loja_aurora*>, avisando que nada está confirmado ainda.

Missão: confirme a reserva de vez: digite BEGIN;, UPDATE produtos SET estoque = 19 WHERE id = 1; e COMMIT;. O psql responde COMMIT e o estoque fica 19 para sempre.

Se a conexão cair no meio…

Esqueceu do COMMIT? O PostgreSQL te protege.

Se a sessão cair (ou o psql fechar) no meio de uma transação, o banco faz ROLLBACK automático — suas operações nunca ficam "pela metade". E se um comando dentro da transação der erro, o PostgreSQL recusa os próximos comandos até você dar ROLLBACK (current transaction is aborted). No PostgreSQL até CREATE TABLE entra na transação: dá para criar a tabela, testar, e dar ROLLBACK para desistir.

ACID: as quatro promessas da transação

LetraPromessaNo nosso exemplo
A — Atomicidadetudo ou nada: ou as 2 operações acontecem, ou nenhumaestoque baixou e pedido criado — ou volta tudo
C — Consistênciaas constraints continuam válidas depois da transaçãopedido sempre aponta para cliente que existe
I — Isolamentooutra sessão não vê a reserva "pela metade"só depois do COMMIT o estoque 19 aparece para os outros
D — Durabilidadedepois do COMMIT, está gravado — mesmo se cair a luzo COMMIT só volta depois de gravar em disco

Resumo

  • Transação = pacote "tudo ou nada": BEGIN abre, COMMIT confirma, ROLLBACK desfaz.
  • Dentro da transação o prompt vira loja_aurora*> — nada está gravado de vez ainda.
  • Use para operações que precisam nascer juntas: baixa no estoque + pedido, transferência entre contas, etc.
  • Se a conexão cair no meio, o PostgreSQL faz ROLLBACK automático — nunca fica pela metade.
  • ACID: atomicidade, consistência, isolamento e durabilidade.
