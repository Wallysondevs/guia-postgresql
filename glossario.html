Glossário de PostgreSQL, de A a Z

Todo guia de banco de dados usa os mesmos termos o tempo inteiro — e eles voltam em todo canto: nos erros do servidor, no psql, nas conversas de trabalho. Este glossário reúne os termos essenciais em ordem alfabética, com definição em português claro e exemplo prático. Consulte sempre que um termo novo aparecer.

Você vai aprender
  • Os fundamentos: banco de dados, tabela, linha, coluna, SQL.
  • As chaves e regras: PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, constraint.
  • A operação: query, JOIN, transação (ACID), SQLSTATE, psql.

Os termos, de A a Z

ACID
As quatro garanties de uma transação: Atomicidade (tudo ou nada), Consistência (as regras/constraints valem), Isolamento (uma transação não vê a outra pela metade) e Durabilidade (depois do COMMIT, está gravado). Aula transações.
Banco de dados (database)
O "arquivo" onde o servidor guarda tudo: tabelas, views, índices e permissões. Um servidor PostgreSQL tem vários bancos (postgres, loja_aurora…) — veja com \l. Você se conecta a um banco por vez no psql (\c troca).
Coluna (column / campo)
Uma propriedade da tabela, com tipo fixo: em clientes, nome é text e estado é char(2). É o cabeçalho da planilha. Veja com \d clientes.
COMMIT
O comando que grava de vez tudo que foi feito desde o BEGIN. Antes dele, dá para desistir com ROLLBACK.
Constraint (restrição)
Regra que o banco impõe na tabela: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT. Quem quebra leva erro com SQLSTATE (cola em ref-erros). Aula constraints.
DDL / DML / DQL
As três famílias de SQL: DDL (estrutura: CREATE, ALTER, DROP), DML (dados: INSERT, UPDATE, DELETE), DQL (consulta: SELECT). Cola em ref-sql.
Esquema (schema)
Uma "pasta" dentro do banco que organiza os objetos. Tudo que você cria cai no public por padrão — por isso o psql mostra public.clientes. Dá para criar esquemas próprios (CREATE SCHEMA loja;) para separar áreas.
FOREIGN KEY (chave estrangeira)
A coluna que aponta para a PRIMARY KEY de outra tabela: pedidos.cliente_id REFERENCES clientes(id). Garante que não exista pedido de cliente fantasma (erro 23503).
Índice (index)
Uma estrutura auxiliar que acelera busca na coluna — como o índice remissivo de um livro. CREATE INDEX idx ON produtos (nome); deixa WHERE nome = … voar. Mas índice demais deixa INSERT lento. Aula índices.
JOIN
O comando que cruza duas tabelas pela chave comum: SELECT c.nome, p.status FROM clientes c JOIN pedidos p ON p.cliente_id = c.id;. Tipos: INNER (só os que têm par), LEFT (todos da esquerda, com ou sem par), RIGHT, FULL. Aula JOINs.
Linha (row / tupla / registro)
Um registro completo da tabela — uma linha da planilha. SELECT * FROM clientes; devolve 5 linhas (no banco de exemplo). O INSERT adiciona linhas; o UPDATE 3 mudou 3 linhas.
NULL
"Sem valor" — diferente de zero e de texto vazio. NULL = NULL dá NULL (use IS NULL para testar). Coluna NOT NULL não aceita. É o espaço em branco da ficha.
Normalização
A arte de organizar as tabelas para não repetir dado: em vez de guardar o nome do cliente dentro do pedido, guarda só o cliente_id (a FK) e busca o nome com JOIN. Evita dado duplicado e inconsistente.
Pool de conexões
Na biblioteca pg (Node.js), o objeto que mantém um grupo de conexões abertas com o servidor e as empresta às requisições (max: 20). Sem pool, cada query abriria e fecharia conexão — lento. Projeto API Node + pg.
PRIMARY KEY (chave primária)
A coluna que identifica cada linha sem repetir — o "CPF" da tabela (geralmente id serial PRIMARY KEY). Única e não nula; violar dá erro 23505.
psql
O cliente de terminal do PostgreSQL — onde você digita SQL e meta-comandos (\dt, \l). Prompt típico: loja_aurora=>. Aula primeiro psql; cola de meta-comandos em ref-psql.
Query (consulta)
Qualquer comando SQL enviado ao servidor — especialmente o SELECT. "Rodei uma query" = mandei um comando pro banco.
ROLLBACK
O comando que desfaz tudo desde o BEGIN — o banco volta ao estado anterior, como se nada tivesse acontecido.
SQL
"Structured Query Language": a linguagem padrão para falar com bancos relacionais. No PostgreSQL, os comandos são em inglês e insensíveis a maiúsculas: select * from clientes; funciona igual a SELECT * FROM clientes;.
SQLSTATE
O código de 5 caracteres que acompanha todo erro do PostgreSQL (ex.: 23505 = chave duplicada, 42P01 = tabela não existe). É o "CPF do erro" — procure na cola de erros.
Tabela (table / relação)
A unidade que guarda os dados: colunas (com tipo) + linhas (registros). É a planilha do banco. Criada com CREATE TABLE, listada com \dt, descrita com \d. Aula banco e tabelas.
Transação (transaction)
Um grupo de comandos que vale inteiro: começa com BEGIN, termina com COMMIT (grava) ou ROLLBACK (desfaz). É o "tudo ou nada" — o pagamento no cartão. Aula transações e projeto reservas.
Trigger (gatilho)
Uma função que o banco dispara sozinha quando acontece INSERT/UPDATE/DELETE numa tabela (ex.: gravar log de auditoria automático).
UNIQUE
A constraint que garante valor sem repetição na coluna — tipo email text UNIQUE. Violação dá erro 23505 (duplicate key value…).
View
Uma consulta salva com nome, que se comporta como tabela de leitura: CREATE VIEW v AS SELECT …; depois SELECT * FROM v;. Não guarda dados — recalcula na hora. Aula views.
serial / bigserial
Tipo prático de id: integer que o banco preenche sozinho em sequência (1, 2, 3…). Por baixo, cria uma sequência + DEFAULT nextval(...).
uuid
Identificador universal de 128 bits ('a0eebc99-9c0b-…'), gerado por gen_random_uuid(). Ótimo como id público de API (não entrega quantos registros existem, diferente do serial).
jsonb
Tipo de documento JSON em formato binário, indexável e consultável (dados->>'cor'). Para dados flexíveis (atributos de produto, configurações). O json guarda o texto cru; o jsonb é o recomendado.
VACUUM / ANALYZE
VACUUM limpa as linhas mortas que sobram de UPDATE/DELETE (o banco não apaga na hora, só marca); ANALYZE atualiza as estatísticas que o otimizador usa para escolher o plano. O autovacuum faz isso sozinho. Aula VACUUM e ANALYZE.
EXPLAIN
O comando que mostra o plano de execução de uma query (como o banco vai buscar os dados: índice ou varredura). EXPLAIN ANALYZE SELECT … executa de verdade e mostra os tempos. Aula EXPLAIN.

Os pares que mais confundem

  • banco × tabela × linha: banco = o arquivo inteiro; tabela = uma planilha dentro dele; linha = um registro da planilha.
  • PRIMARY KEY × FOREIGN KEY × UNIQUE: PK identifica a linha; FK aponta para a PK de outra tabela; UNIQUE só proíbe repetição (permite um NULL).
  • INNER JOIN × LEFT JOIN: INNER só traz quem tem par nas duas tabelas; LEFT traz todos da esquerda, com NULL quando não há par.
  • WHERE × HAVING: WHERE filtra linhas antes de agrupar; HAVING filtra grupos depois do GROUP BY.
  • text × varchar(n) × char(n): text sem limite (preferido); varchar com limite; char de tamanho fixo preenchido com espaços.
  • numeric × real: numeric é exato (dinheiro); real é ponto flutuante aproximado (medição científica).
  • timestamp × timestamptz: sem fuso vs. com fuso (o tz guarda em UTC e converte na hora de mostrar — use ele).
  • json × jsonb: json guarda o texto cru; jsonb guarda binário, indexável e mais rápido — prefira jsonb.
  • COMMIT × ROLLBACK: COMMIT grava a transação; ROLLBACK desfaz. Os dois fecham a transação aberta pelo BEGIN.
  • DDL × DML: DDL muda a estrutura (CREATE TABLE); DML muda os dados (INSERT).
