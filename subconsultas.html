Subconsultas e CTEs (WITH)

Às vezes a pergunta precisa de duas etapas: "quais clientes fecam pedido?" primeiro você olha a tabela de pedidos, depois filtra os clientes. A subconsulta faz isso dentro de um único comando — é uma SELECT dentro de outra, como uma pergunta dentro da pergunta. O WITH (CTE) serve para dar nome a essas consultas internas e deixar tudo legível.

Você vai aprender
  • Subconsulta com IN no WHERE;
  • Subconsulta escalar (com =, >) — deve voltar uma única linha;
  • EXISTS — "só importa que exista";
  • Subconsulta no FROM (tabela derivada);
  • CTEs com WITH nome AS (...), inclusive várias de uma vez;
  • O erro more than one row returned by a subquery;
  • Praticar no simulador de psql.

Subconsulta com IN no WHERE

A pergunta "quais clientes fecam pedido?" em duas etapas: (1) pegue os cliente_id da tabela de pedidos; (2) filtre os clientes cujo id está nessa lista. O IN (SELECT ...) junta as duas etapas:

loja_aurora=> SELECT nome FROM clientes
             WHERE id IN (SELECT cliente_id FROM pedidos);
    nome
------------
 Ana Souza
 Beto Lima
(2 rows)

A subconsulta de dentro roda primeiro e entrega a lista (1, 2, 1); depois o WHERE de fora mantém só os clientes cujo id está na lista. Pense nela como um conjunto de valores entre parênteses.

SELECT nome FROM clientes
a consulta de fora (a pergunta principal)
WHERE id IN (...)
filtra pelo conjunto de ids
SELECT cliente_id FROM pedidos
a subconsulta: roda primeiro e alimenta o IN

Subconsulta escalar: um valor só

Também dá para comparar com o resultado de uma agregação — "quais produtos custam acima da média?":

loja_aurora=> SELECT nome, preco
             FROM produtos
             WHERE preco > (SELECT AVG(preco) FROM produtos);
   nome   | preco
----------+-------
 Camiseta | 59.90
 Boné     | 49.90
(2 rows)

A média é 32.82, então só Camiseta e Boné passam. Esse tipo de subconsulta (com =, >, <) se chama escalar: ela precisa devolver exatamente um valor.

Se a subconsulta escalar voltar mais de uma linha, o PostgreSQL para tudo 
loja_aurora=> SELECT nome FROM clientes WHERE id = (SELECT cliente_id FROM pedidos);
ERROR:  more than one row returned by a subquery used as an expression

A tabela pedidos tem 3 linhas, então = (SELECT cliente_id ...) não faz sentido. Nesse caso, use IN (várias linhas) — ou agregue a subconsulta para virar um valor só.

EXISTS: só importa que exista

Quando você não quer o valor, só quer saber se existe algo, o EXISTS é mais direto (e o PostgreSQL para na primeira linha encontrada — é rápido):

loja_aurora=> SELECT nome FROM clientes c
             WHERE EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.id);
    nome
------------
 Ana Souza
 Beto Lima
(2 rows)

Tradução: "me dê os clientes para os quais existe pelo menos um pedido ligada a eles". A subconsulta de dentro é correlacionada: ela usa c.id da linha de fora — cada cliente testa a própria subconsulta.

Subconsulta no FROM: tabela derivada

Uma subconsulta também pode aparecer no FROM, como se fosse uma tabela temporária (por isso precisa de apelido, aqui resumo):

loja_aurora=> SELECT estado, total
             FROM (SELECT estado, COUNT(*) AS total FROM clientes GROUP BY estado) AS resumo
             WHERE total > 1;
 estado | total
--------+-------
 PI     |     3
(1 row)

Primeiro a "tabela" resumo é calculada (contagem por estado); depois o SELECT de fora filtra o resultado. É como salvar o rascunho numa gaveta e continuar trabalhando em cima dele.

CTE: WITH dá nome à subconsulta

Consultas grandes com várias subconsultas aninhadas viram uma sopa de parênteses. O WITH resolve isso dando nome a cada etapa — como batizar cada gaveta do arquivo:

loja_aurora=> WITH clientes_pi AS (
               SELECT * FROM clientes WHERE estado = 'PI'
             )
             SELECT nome FROM clientes_pi;
   nome
-----------
 Ana Souza
 Beto Lima
 Eva Nike
(3 rows)
WITH clientes_pi AS (...)
declara a CTE: uma consulta com nome, válida só dentro deste comando
SELECT nome FROM clientes_pi
usa a CTE como se fosse uma tabela comum

E dá para declarar várias CTEs separadas por vírgula, cada uma usando a anterior:

loja_aurora=> WITH pedidos_por_cliente AS (
               SELECT cliente_id, COUNT(*) AS total FROM pedidos GROUP BY cliente_id
             )
             SELECT c.nome, pc.total
             FROM clientes c
             JOIN pedidos_por_cliente pc ON pc.cliente_id = c.id;
   nome    | total
-----------+-------
 Ana Souza |     2
 Beto Lima |     1
(2 rows)

Leitura de cima para baixo, como um roteiro — muito mais legível que parênteses dentro de parênteses.

Missões no simulador

O simulador executa as peças que compõem subconsultas (IN com lista, JOIN, WHERE). Pratique as consultas equivalentes:

Missão 1: "quem fez pedido?" sem subconsulta: junte clientes e pedidos com JOIN. A saída mostra Ana Souza.

Missão 2: "produtos acima de 30 reais" (a subconsulta seria preco > (SELECT AVG(preco) ...)): SELECT nome FROM produtos WHERE preco > 30; — a saída mostra Boné.

Missão 3: pratique filtro composto com AND (é assim que a subconsulta afinaria o resultado): SELECT nome FROM clientes WHERE estado = 'PI' AND id > 1; — só Beto e Eva, ou seja (2 rows).

Missão 4: junte duas condições com OR: SELECT nome FROM clientes WHERE estado = 'SP' OR estado = 'PE'; — a saída mostra Carla Reis (SP) e Diego (PE).

Resumo

  • Subconsulta = SELECT dentro de SELECT; a de dentro roda primeiro.
  • IN (SELECT ...) para listas; = > < (SELECT ...) exige um valor só (escalar); EXISTS para "existe?".
  • No FROM, a subconsulta vira tabela derivada e precisa de apelido.
  • WITH nome AS (...) cria CTEs legíveis, várias seguidas, cada uma usando a anterior.
  • Erro clássico: more than one row returned by a subquery used as an expression.
